# Security Policy & Threat Model

## Honest Security Guarantees

SentinelBox implements **user-space transactional isolation** and **deterministic verification**. It is designed to prevent accidental damage, bad code mutations, and unverified diffs generated by AI coding agents.

### What SentinelBox Protects Against
- Unverified syntax errors or failing test suites reaching the live workspace.
- Accidental recursive file deletions (`rm -rf`, Windows drive deletes).
- Path traversal escapes (`../`, symlinks pointing outside root, UNC paths).
- Concurrent workspace overwrites (TOCTOU conflicts).
- Secret leaks in audit logs (automatic redaction of API keys, tokens, and private keys).

### What User-Space Sandboxing Does NOT Protect Against
- Root/Kernel level exploits by a deliberately malicious agent binary running with elevated privileges.
- Covert timing side-channels.
- Native kernel syscall escapes without container/VM virtualization.

For fully hostile, untrusted binaries, pair SentinelBox with Level 4 Container/VM backends (e.g., Docker, Podman, or gVisor).
